# 基于 LLM Agent 的 YOLO 超参数自动调优

## —— 以 PCB 缺陷检测为例

> **阅读说明（维护者补充）**
>
> 本文档的数字全部可在 [`experiments/results_pcb_backup.tsv`](../experiments/results_pcb_backup.tsv)
> 中逐行核对：初始配置 `0.7568` → 16 轮 LLM 决策 → 最终 `0.783617 / 0.555783`。
>
> 需要特别说明的一点：文中"随机搜索 16 轮停滞在 0.7568"这一组对比，其随机部分实际上是**失效的**——
> TSV 第 2–16 行给出的是同一个配置（`0.741739` 重复 15 次），原因是当时 ultralytics 训练内部
> 调用了 `set_seed()` 重置全局随机数状态，该 bug 已在 `policy/random.py` 中修复。
> **因此该对比不能作为受控实验引用**；站得住脚的结论是"LLM 在 16 轮内把人工初始配置提升了 3.5%"。
> 详见 [`experiments/README.md`](../experiments/README.md)。

## 摘要

提出一种基于大语言模型（LLM）的闭环 Agent 框架，用于 YOLO 目标检测模型的超参数自动调优。该框架通过 LLM 分析历史实验记录、提出优化假设、生成新配置，并结合简化原则（Simplicity Criterion）避免无效复杂度累积。在 PCB 缺陷检测数据集（449 训练/100 验证，6 类）上，LLM Agent 将 yolo26n scratch 模型的 mAP50 从 0.676 提升至 0.784（+16.0%），mAP50-95 从 0.424 提升至 0.555（+30.9%），所有 6 类缺陷检测精度均显著提升。对比实验表明，LLM 驱动的定向搜索在相同预算下显著优于随机搜索。

## 1. 问题背景

### 1.1 工业场景

PCB（印刷电路板）缺陷检测是电子制造质量控制的关键环节。数据集包含 6 类常见缺陷：

| 类别 | 编号 | 中文 | 说明 |
|---|---|---|---|
| open | 0 | 开路 | 电路断开 |
| short | 1 | 短路 | 不应连接的电路相连 |
| mousebite | 2 | 缺口 | 线路边缘缺损 |
| spur | 3 | 毛刺 | 多余金属突出 |
| pinhole | 4 | 针孔 | 小孔缺陷 |
| spurious_copper | 5 | 伪铜 | 不应有的铜 |

**数据规模**：449 张有标注训练图片 + 100 张验证图片，总标签数 681 个，平均每类约 91 个标注实例。属于典型的工业小数据集场景。

### 1.2 核心痛点

YOLO 超参数调优长期依赖人工经验：
- **搜索空间大**：学习率、损失权重、数据增强等 18+ 维超参数
- **试错成本高**：每次训练需数分钟到数小时
- **不可解释**：传统 AutoML（Optuna、贝叶斯优化）只输出参数，无法解释调优策略
- **数据稀缺**：工业场景标注成本高，模型容易过拟合

### 1.3 本项目目标

构建一个 **LLM 驱动的闭环 Agent**，使其能够：
1. 读取历史实验记录，自主分析趋势
2. 提出有依据的超参数假设
3. 执行训练评估，记录结果
4. 持续迭代，自动探索最优配置

## 2. 方法

### 2.1 系统架构

```
┌─────────────────────────────────────────────────────────┐
│                    LLM Agent 闭环                        │
│                                                         │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐         │
│   │ TSV 历史  │───▶│   LLM    │───▶│ YOLO训练  │         │
│   │ (实验记录) │    │ (DeepSeek)│   │ (微调50轮) │         │
│   └──────────┘    └──────────┘    └──────────┘         │
│         ▲                               │                │
│         │                               ▼                │
│         │          ┌──────────┐    ┌──────────┐         │
│         └──────────│ 简化判断  │◀───│ 评估mAP   │         │
│                    │ (保留/丢弃) │    │          │         │
│                    └──────────┘    └──────────┘         │
└─────────────────────────────────────────────────────────┘
```

### 2.2 LLM 策略生成

每轮实验开始前，Agent 将以下信息发送给 DeepSeek：

1. **超参数搜索空间**：18 个参数的取值范围
2. **最近 5 轮实验记录**：含 mAP50、状态（keep/discard）、配置描述
3. **当前全局最佳配置**：含完整超参数和 mAP 值

LLM 系统提示核心约束：

> - 调优优先级：lr0/lrf > box/cls/dfl > 数据增强 > 正则化
> - PCB 小目标：增大 box 损失增益，降低过强数据增强
> - 只能在搜索空间内调整参数（不调 imgsz 等外部参数）
> - 微调模式（20 epoch），学习率不宜过大
> - 输出分析 + YAML 配置 + 实验描述

### 2.3 简化原则 (Simplicity Criterion)

| 条件 | 决策 |
|---|---|
| mAP 提升 > 阈值 (0.002) | 无条件保留 |
| mAP 下降 | 丢弃 |
| mAP 提升 ≤ 阈值 且 新配置更复杂 | 丢弃（保留简化版） |
| mAP 持平 且 配置不更复杂 | 保留 |

复杂度定义为数据增强数量（mosaic / mixup / copy_paste / degrees / shear / dropout）。

### 2.4 搜索空间与超参数

| 类别 | 参数 | 范围 |
|---|---|---|
| 学习率 | lr0 | [0.001, 0.02] |
| | lrf | [0.001, 0.1] |
| 优化器 | momentum | [0.85, 0.95] |
| | weight_decay | [0.0001, 0.001] |
| | warmup_epochs | [2.0, 5.0] |
| 损失权重 | box | [5.0, 15.0] |
| | cls | [0.3, 1.0] |
| | dfl | [1.0, 3.0] |
| 数据增强 | hsv_h/s/v | [0, 0.05/0.8/0.6] |
| | degrees | [0, 10.0] |
| | translate | [0, 0.2] |
| | scale | [0, 0.5] |
| | shear | [0, 5.0] |
| | mosaic | [0, 1.0] |
| | mixup | [0, 0.3] |
| | copy_paste | [0, 0.3] |
| 正则化 | dropout | [0, 0.1] |

### 2.5 工程保障

- **OOM 自动恢复**：5 级降级机制（batch: 4→2→2→1→1, imgsz: 640→480→320）
- **早停机制**：连续 10 轮无全局最佳提升自动终止
- **配置回滚**：每轮 discard/crash 后自动恢复至历史最佳配置
- **权重管理**：保留 top-3 最佳模型，自动清理旧实验目录

## 3. 实验设计

### 3.1 基线模型

| 实验 | 模型 | 参数量 | 起点 | 基线 mAP50 | 基线 mAP50-95 |
|---|---|---|---|---|---|
| Exp1 | yolo26s | 9.5M | train2 best.pt (预训 100 epoch) | 0.8549 | 0.5658 |
| Exp2 | yolo26n | 2.5M | scratch best.pt (从零训 150 epoch) | 0.6815 | 0.4229 |

### 3.2 实验流程

```
Exp1 (yolo26s):  随机搜索 × 22轮 (50 epoch/轮) → 最佳 0.9032

Exp2 (yolo26n):
  ├── Stage 1: 随机搜索 + LLM(bug) × 17轮 → 最佳 0.7465
  └── Stage 2: 随机搜索 × 16轮 → 0.7568
               LLM Agent × 15轮  → 最佳 0.7836
```

> Stage 1 中 LLM 被系统提示中 "增大 imgsz" 引导误导，持续调整 imgsz（800/960/1024/1280）导致无效实验。修复后 Stage 2 的 LLM 不再触碰 imgsz，专注于搜索空间内的参数。

## 4. 核心结果

### 4.1 总体对比

| 实验 | 策略 | 最佳 mAP50 | 最佳 mAP50-95 | 起点→最佳提升 |
|---|---|---|---|---|
| Exp1 (yolo26s) | 随机搜索 | **0.9032** | **0.6479** | +5.6% / +14.5% |
| Exp2 (yolo26n) | LLM Agent | **0.7836** | **0.5558** | +15.0% / +31.4% |

> yolo26s 参数多 3.8 倍，精度更高；但 yolo26n 的提升幅度更大，证明方法对小模型效果显著。

### 4.2 LLM vs 随机搜索同预算对比 (Exp2 Stage 2)

| 阶段 | 轮数 | 最佳 mAP50 | 趋势 |
|---|---|---|---|
| 随机搜索 | 16 | 0.7568 | 全卡在 0.74 |
| **LLM Agent** | **15** | **0.7836** | 持续上升 |

```
LLM Agent 探索轨迹：
0.7568 → 0.7575 → 0.7682 → 0.7733 → 0.7785 → 0.7836
```

在相同的 15 轮预算内，LLM Agent 每 3-4 轮就能找到一个新最佳，而随机搜索 16 轮完全停滞。

### 4.3 各类别缺陷检测精度

| 类别 | 原始 mAP50 | LLM 最终 mAP50 | 提升 | P 变化 | R 变化 |
|---|---|---|---|---|---|
| open (开路) | 0.759 | **0.827** | +0.068 | 0.648→0.777 | 0.697→0.736 |
| **short (短路)** | **0.558** | **0.723** | **+0.165** | 0.719→0.787 | 0.432→0.602 |
| **mousebite (缺口)** | **0.712** | **0.861** | **+0.149** | 0.704→0.856 | 0.588→0.765 |
| spur (毛刺) | 0.641 | 0.762 | +0.121 | 0.689→0.810 | 0.604→0.615 |
| pinhole (针孔) | 0.515 | 0.609 | +0.094 | 0.495→0.500 | 0.840→0.800 |
| spurious_copper (伪铜) | 0.871 | 0.920 | +0.049 | 0.768→0.888 | 0.817→0.853 |

| 整体指标 | 原始 | LLM 最终 | 提升 |
|---|---|---|---|
| **mAP50** | 0.676 | **0.784** | **+0.108 (+16.0%)** |
| **mAP50-95** | 0.424 | **0.556** | **+0.132 (+31.1%)** |
| Precision | 0.670 | 0.770 | +0.100 |
| Recall | 0.663 | 0.728 | +0.065 |

**关键发现**：
- **所有 6 类缺陷检测精度全部提升**，无一退步
- short（短路）和 mousebite（缺口）提升最显著（+0.165 和 +0.149）
- 精度提升同时查全率也提高（+6.5%），说明模型既找到了更多缺陷，也找得更准
- mAP50-95 提升幅度（+31.1%）远超 mAP50（+16.0%），说明 **定位精度改善尤为突出**

### 4.4 LLM 发现的最优配置

```yaml
lr0: 0.008          # 较低学习率，适合微调
lrf: 0.008
momentum: 0.937
weight_decay: 0.0005
box: 15.0           # ⭐ 最大 box 损失权重（搜索空间上限）
cls: 0.5
dfl: 1.5
mosaic: 0.1         # ⭐ 极低 mosaic 增强
mixup: 0.04         # ⭐ 极低 mixup 增强
copy_paste: 0.1
degrees: 2.0
dropout: 0.05
```

**LLM 的自主发现**：PCB 小缺陷检测需要（1）最大化 box 定位损失 （2）最小化破坏细节的数据增强，（3）用适度低学习率精细调整。这一规律与目标检测领域"小目标增大 box 权重"的经验一致，但 LLM 通过实验数据独立发现了它。

## 5. LLM 决策过程分析

以下是 LLM Agent 在关键轮次生成的真实分析：

**第 3 轮（首次 LLM）**：
> 分析: 当前最佳配置为空，说明之前仅有一次有效随机搜索（mAP=0.7465）。由于是 PCB 缺陷检测（小目标场景），应优先增大 box 损失权重。同时 lr0 可尝试接近上限以加速收敛，并适当降低数据增强强度以简化训练。

**第 7 轮（发现低增强有效）**：
> 分析: 降低 lr0 至 0.006，微调 mosaic 至 0.25 和 mixup 至 0.08

**第 13 轮（逼近最终配置）**：
> 分析: 微调 lr0 至 0.0075，增大 box 至 14.5

**第 17 轮（最终最佳）**：
> 分析: 增大 box 至 15.0，降低 mosaic 至 0.1，微调 lr0 至 0.008

LLM 表现出清晰的搜索策略：先锁定方向（box↑ + 增强↓），然后精细调参（lr0 在 0.005-0.01 间试探）。这种**先粗后细**的探索模式与人类专家调参逻辑高度一致。

## 6. 创新点

| 创新 | 具体实现 | 传统方法对比 |
|---|---|---|
| **LLM 替代传统搜索** | DeepSeek 读 TSV 历史 → 分析趋势 → 定向建议 | Optuna/网格搜索无记忆、无解释 |
| **闭环自学习** | 实验结果反哺下轮决策，越跑越聪明 | Ray Tune 每次独立运行 |
| **简化原则** | 自动惩罚无效复杂度，偏好简洁配置 | 传统方法只关注指标最大化 |
| **可解释调优** | LLM 输出分析文本，知悉"为什么这么调" | 贝叶斯优化只输出参数数值 |
| **工业小数据验证** | 449 张图，6 类缺陷，真实工业场景 | 多数 AutoML 论文在 ImageNet 级数据上验证 |
| **框架无关性** | 换数据集/模型/LLM 只需改配置 | — |

## 7. 遇到的挑战与解决方案

| 挑战 | 现象 | 解决 |
|---|---|---|
| GPU 显存不足 | RTX 4060 8GB, batch=8 时 OOM | 5 级自动降级（4→2→2→1→1） |
| LLM 被系统提示误导 | 持续调 imgsz(800→960→1024→1280) | 修改 prompt + 过滤非搜索空间参数 |
| openai 库兼容性 | `__init__() got an unexpected key` | 替换为原生 requests 调用 |
| 环境变量丢失 | 每次新终端 key 为空 | 文档强调同终端设 + 运行 |
| 权重保存路径不匹配 | ultralytics 实际存 `runs/detect/` | 修正为 `runs/detect/project/name/` |
| 清理函数误删源模型 | 源模型在 runs 目录会被清掉 | 复制到 `models/` 持久目录 |
| 小模型性能天花板 | yolo26n 在 0.78 附近停滞 | 确认已达容量极限，需更大模型 |

## 8. 结论与展望

### 8.1 结论

1. LLM Agent 框架在 PCB 缺陷检测任务上，将 yolo26n scratch 模型的 mAP50-95 提升 31.1%，所有 6 类缺陷检测精度全面提升。
2. 在相同实验预算下（15 轮），LLM 驱动的定向搜索显著优于随机搜索（0.784 vs 0.757）。
3. LLM 自主发现的最优方向（高 box + 低增强）与目标检测领域专家经验一致，证明了其分析能力。
4. 框架具备良好的鲁棒性（OOM 恢复、配置回滚）和可迁移性（模型/数据集/LLM 均可替换）。

### 8.2 展望

| 方向 | 内容 |
|---|---|
| 多模态 Agent | 将训练曲线图、混淆矩阵也喂给 LLM 分析 |
| 本地化部署 | 用本地模型（Qwen/Llama）替代云端 API |
| 泛化验证 | 扩展到 YOLO 分类/分割/关键点任务 |
| 深度优化 | 支持自动调整模型架构（深度/宽度/head 设计） |
| 强化学习适配 | 将 env 模块抽象化，支持 RL/分类等场景 |
